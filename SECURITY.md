# Security and publication boundary

The default frontend loads fictional public configuration and never initializes sign-in or contacts a backend. The auth source and optional provider shell are included for separate reviewed integration. No client secret, deployment token, real tenant/client ID or employee data is published.

Actual runtime/API/experience modules are adapted with neutral values. Two browser URL validation hardenings are explicit public changes; private platform files are untouched. Client routing, visibility flags, CORS and CSP do not replace backend authorization.

The manual workflow builds/tests/stages without Azure credentials or uploads. The inert SWA publication excerpt is not executable automation and uses an intentionally unfilled immutable-commit placeholder. Real token retrieval, deployment, domains, API settings and hosted acceptance remain separately owned operations.

Ignore installed dependencies, dist, destination staging, secrets and Terraform state/plans. Do not publish private form files, raw release logs or source history. No cloud setting, service or domain is changed by this portfolio task.
